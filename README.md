# Token 消耗打卡台

## 项目简介

本项目面向个人使用，目标是用一个无需登录、无需后端、可离线运行的工作台，把“记录消耗、核对账户、查看趋势、备份数据”放在一起。

1. 本地优先：数据默认保存在当前设备，不要求账号和网络，适合个人隐私数据。
2. 账户与记录分离：打卡记录保存实际消耗快照，账户余额通过账户流水维护，编辑、删除和退款可以追溯。
3. 单文件交付：页面、样式、Chart.js 和应用逻辑集中在一个 HTML 文件中，复制即可试用。
4. 渐进式交互：首页先展示最重要的提醒和统计，详细流水、校准和健康检查按需展开。
5. 宽屏与窄屏兼容：同一套页面适配桌面浏览器和手机浏览器，避免为试玩者准备多套版本。

### 可用功能概览

使用者可以完成以下流程：

```text
配置平台和模型
      ↓
按次记录 token 与费用
      ↓
自动换算人民币金额并扣减平台余额
      ↓
在首页/看板查看目标、趋势和成本
      ↓
通过流水、健康检查和 JSON 备份进行核对与恢复
```

## 功能

- 首页概览：今日待处理、本周打卡、统计卡片、每月目标、账户余额和最近记录。
- Token 打卡：记录日期、平台、模型、场景、token 消耗、消费金额、实际人民币金额、倍率和备注。
- 数据看板：查看 14 天趋势、模型用量占比、7 天消费金额和周期统计图表。
- 历史记录：按月份、平台、模型和关键词筛选，支持编辑、删除和分批加载。
- 账户管理：维护平台充值比率和余额，记录充值、消费、退款、校准等账户流水。
- 供应商配置：维护模型输入/输出价格，并将模型关联到多个平台。
- 主题切换：提供五套可持久化主题。
- 数据备份：支持 JSON 完整备份、CSV 导出、合并/覆盖恢复和备份记录查看。
- 数据维护：支持数据健康检查以及按账户流水重建平台余额。
- 响应式布局：桌面端侧边栏、移动端底部导航、移动端历史卡片和图表自适应。

## 快速开始

### 直接打开单文件

双击打开：

```text
index.html
```

首次使用建议先进入“设置”，添加平台和模型，再进入“打卡”页面录入记录。

项目不要求账号、登录、后端服务或联网请求。所有页面资源已内联，可离线使用。

### 使用本地 HTTP 服务

浏览器对 `file://` 页面的本地存储策略可能不同。需要更稳定的浏览器存储或测试本地 HTTP 时，可在项目目录启动静态服务器：

```powershell
python -m http.server 8000
```

然后打开：

```text
http://localhost:8000/index.html
```

停止服务时按 `Ctrl+C`。本地 HTTP 服务仅用于访问页面，不会自动把数据上传到网络。

## 数据存储与备份

数据结构包含以下主要部分：

```text
records        打卡记录
settings       平台、模型、目标和主题设置
accountLedger  账户流水
meta           迁移、备份和写入时间信息
```

存储策略：

- IndexedDB 是主存储，数据库名为 `wb_token_data_db`，对象仓库为 `state`。
- localStorage 保留旧数据迁移能力，并在 IndexedDB 不可用时作为降级存储。
- 页面启动时会比较 localStorage 和 IndexedDB 快照的 `lastWriteAt`，尽量保留更新的数据。
- IndexedDB 可用时会请求浏览器持久存储权限，减少数据被浏览器自动回收的概率。
- 账户余额由账户流水计算，平台余额是可重建的缓存。

### `file://` 注意事项

直接双击 HTML 属于 `file://` 模式。不同浏览器对该模式的 IndexedDB 和 localStorage 支持可能不同。

查看侧边栏同步状态：

- `IndexedDB 已连接`：当前使用 IndexedDB 主存储。
- `降级存储，请定期备份`：IndexedDB 不可用，当前使用 localStorage。
- `存储不可用（离线）`：保存失败，需要立即导出备份并检查浏览器存储权限。

重要数据建议定期点击“导出 JSON”。更换浏览器、设备或访问地址后，通过“导入恢复”迁移数据。不同浏览器、不同域名和 `file://` 页面之间不会共享 IndexedDB 数据。

## 备份与恢复

- JSON 备份包含完整账户、记录、流水、设置和备份元数据。
- 覆盖恢复会替换当前完整快照。
- 合并恢复会追加记录，并避免重复改变当前账户余额。
- CSV 适合在 Excel 等工具中查看，不用于完整恢复。
- 删除浏览器网站数据、清理应用数据或更换设备前，先导出 JSON。

## 开始试用

### 使用步骤

1. 下载仓库或 ZIP，并用 Chrome、Edge 等现代浏览器打开 `index.html`。
2. 首次进入“设置 → 账户管理”，添加自己实际使用的平台、充值比率和初始平台余额。
3. 进入“设置 → 供应商配置”，添加模型的输入/输出价格，并关联可用平台。
4. 进入“打卡”，填写 token 消耗和费用，保存后检查平台余额是否按预期扣减。
5. 在首页和“数据看板”查看本周打卡、每月目标、趋势和费用统计。
6. 试用结束或更换设备前，点击“导出 JSON”保存自己的完整数据。

如果只想体验界面，可以直接使用内置的合成示例记录；如果要记录真实数据，建议先清空示例记录，再配置自己的平台和模型。

### 更稳定的试用方式

直接双击 HTML 最方便，但属于 `file://` 模式，浏览器对本地存储的处理存在差异。给多人长期试用时，可以把整个目录放在静态 HTTPS 地址，或让试用者在本机启动 HTTP 服务：

```powershell
python -m http.server 8000
```

然后访问 `http://localhost:8000/index.html`。静态服务器只提供页面文件，项目数据仍保存在每位试用者自己的浏览器中，不会自动上传或互相可见。

### 是否需要清空你的数据

通常不需要清空。项目的个人数据保存在浏览器的 IndexedDB/localStorage 中，不写入 `index.html` 文件；复制或上传 HTML 不会把你当前浏览器里的账户、流水和打卡记录一起发送给别人。

以下情况需要特别处理：

- 不要把包含个人数据的 JSON 备份一起发送给试用者；如需提供演示数据，先制作一份不含隐私的演示备份。
- 如果让别人使用同一台电脑、同一个浏览器配置，并打开相同的 `file://` 文件或相同的网址，他们可能看到同一份本地数据。应让对方使用自己的浏览器用户配置，或先导出你的 JSON 后清理该浏览器的站点数据。
- 如果你把项目部署到 HTTPS 地址，不同设备和不同浏览器通常拥有各自独立的数据空间；但同一浏览器配置仍然会共享该网址的数据。
- 如果要把电脑交给别人使用，先导出 JSON，再清理浏览器网站数据和 IndexedDB；清理前确认备份文件可正常导入。

### 试用反馈建议

可以请试用者重点反馈：

- 是否能理解“消费金额（$）”与“实际金额（￥）”的区别；
- 平台充值、余额扣减和校准是否符合实际使用习惯；
- 首页提醒和看板统计是否足够；
- 在手机窄屏或不同浏览器中是否出现布局问题；
- 导出 JSON、导入恢复和数据健康检查是否易于找到。

## 开发与构建

源文件位于 `build/`：

```text
build/shell.html      页面结构和样式
build/app.js          应用逻辑
build/chart.umd.js    内联 Chart.js v4.4.1
build/build.js        单文件构建脚本
build/smoke.js        轻量 DOM 桩冒烟测试
```

修改 `build/shell.html` 或 `build/app.js` 后，在 `build/` 目录执行：

```powershell
node build.js
node smoke.js
node --check app.js
```

也可以从项目根目录执行：

```powershell
node .\build\build.js
node .\build\smoke.js
node --check .\build\app.js
```

构建脚本会重新生成项目根目录下的 `index.html`。不要直接编辑该文件；下次构建会覆盖其中内容。

## 技术说明

- 原生 HTML、CSS 和 JavaScript，无前端框架依赖。
- Chart.js v4.4.1 完整内联，无运行时 CDN 请求。
- 使用 hash 路由实现五个页面切换，并支持浏览器后退。
- 使用 Canvas 粒子背景；检测到 `prefers-reduced-motion` 时自动降低动画效果。
- 使用 `ResizeObserver` 触发图表尺寸更新，适配窗口和页面区域变化。
- 金额单位保持项目原有约定；token 在界面中以 M token 展示。

## 公开仓库隐私检查

- 本项目不包含账号体系、后端接口、API 密钥或自动上传逻辑。
- 数据只保存在运行者自己的浏览器 IndexedDB/localStorage 中；仓库文件不包含运行者的数据。
- 内置记录仅用于演示，不代表作者的真实使用数据。
- 发布前应确认仓库历史和待提交文件中没有 JSON/CSV 备份、截图、日志、浏览器导出文件或个人备注。
- 不要把本机绝对路径、用户名、工作区名称写入 README、源码、提交信息或 issue 附件。
- `.gitignore` 只对未跟踪文件生效；如果备份曾经提交过，必须从 Git 历史中清理后再公开仓库。
- GitHub 仓库只是下载渠道，不提供云同步；每位使用者的数据彼此独立。

## 当前限制

- 项目是个人本地工具，不包含账号体系、云同步和多人协作。
- 不同设备之间不会自动同步数据，需要通过 JSON 手动迁移。
- `file://` 模式的存储可靠性取决于浏览器；长期使用建议使用本地 HTTP 地址或定期备份。
- 当前测试包含 Node.js DOM 桩和静态检查，未覆盖所有浏览器的真实 IndexedDB 行为。
